## Review of round 1: the verdict was reject, two blocking findings
1. **BLOCKING 1, the start page's bind.** The page is now published on its own setting, `LAB_PAGE_BIND` (default `127.0.0.1`), and `make up` refuses any other value by name as its first act, before the Docker check and before any container starts: `refused: LAB_PAGE_BIND=0.0.0.0 is not a loopback address…`. Controls in `go test ./lab`: `TestGoLiveThePageIsLoopbackOnly` changes exactly the bind value (four non-loopback values refused by name, three loopback values accepted); `TestGoLiveUpRefusesAPageBindThatIsNotLoopbackBeforeItStartsAnything` runs `up.sh` with a stand-in `docker` that records calls: with `0.0.0.0` it is never called, with `127.0.0.1` it is. Negative control run: the compose line put back on `LAB_BIND` turned `TestGoLiveThePageIsLoopbackOnly` and `TestEveryPublishedPortBindsToTheLabAddress` red; reverted.
2. **BLOCKING 2, the render path.** `lab/seed/render.sh` no longer writes a work file. One `sed | awk` pipe writes one staging file inside the page volume with mode 0600, moves it into place, and removes it on any stop (trap). The password reaches `awk` through its environment, not a command line. Controls: the render test now runs with a private temp directory and a stand-in `awk` that, at the moment the password is about to flow, records what the volume and the temp directory hold: the staging file is in the volume, mode `-rw-------`, and the temp directory is empty; no file outside the volume holds the password, raw or escaped. `TestTheStartPageRenderThatStopsLeavesNoCopyOfThePassword` makes the render stop between the stages (an unfilled placeholder found after the password was written) and requires an empty volume and no copy anywhere. Negative control run: staging moved to the temp directory turned the render test red; reverted.
3. **The remark about `TestTheBannerCheck` on macOS.** BSD `script(1)` stops when its own stdin is not a terminal, which is how `go test` runs the check. On BSD the terminal case now runs only when stdin is a terminal; otherwise it is skipped by name: `banner-check: terminal case NOT RUN: BSD script(1) needs a terminal on stdin and this run has none`. It is never reported as passed. **Not measured on a Mac:** this seat has Linux only, so that the macOS failure was this cause is a reading of the BSD tool's behaviour, not a measurement.
