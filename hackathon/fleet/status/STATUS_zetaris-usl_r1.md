## Summary
A small semantic layer over Proven's evidence (four entity views and one relation view in a `px_usl` container), one data-quality rule that gates it, an idempotent apply script with `DRY=1`, a parity test against sample mode, and the docs. Nothing was sent to Zetaris: the leg had no network and no credential. The layer is **not applied and not measured live**. One setting was added, `PROVEN_OSV_ID_VIEW`, because `osv-by-advisory` had no name setting.

## Acceptance, item by item
1. **The layer.** `lab/zetaris/usl/layer.sql`: `px_package`, `px_advisory`, `px_kev_cve`, `px_epss_score`, and `px_package_evidence` (the relations, all `LEFT JOIN`). Each view is commented with its source and key. `go test ./internal/usl` (`TestLayerDefinesTheFourEntitiesAndTheRelations`, `TestEveryViewNamesItsSourceAndKey`, `TestRelationViewKeepsRowsWithNoMatch`): pass.
2. **The gate.** `lab/zetaris/usl/gate.sql`, rule `usl-epss-score-valid`: every EPSS score and percentile is a number from 0 to 1 and every `cve_id` matches Proven's format. Chosen because Proven keeps the highest `epss` on a finding with no upper bound, and an inner join drops a malformed id silently. Mutated field: the `epss` of one row, `0.50000` to `42` (`TestGateReturnsTheViolatingRow`), and eight single-field mutations (`TestGateSeesEachGuardedFieldAlone`): each returns exactly one row. The clean fixture returns none. `apply.sh` exits 4 naming the rule and the count (`TestApplyRefusesWhenTheGateReturnsARow`), exits 5 when the count cannot be read (`TestApplyRefusesAnUnreadableGateAnswer`). With the check loosened from `-gt 0` to `-gt 5` the refusal test went red; restored, green.
3. **Templates through the layer.** The template SQL is unchanged. Three templates are served by existing settings (`PROVEN_OSV_TABLE`, `PROVEN_KEV_VIEW`, `PROVEN_EPSS_VIEW`). `osv-by-advisory` was **not** servable by a setting: it had none. `PROVEN_OSV_ID_VIEW` was added, following `PROVEN_KEV_VIEW`. Sample mode does not read it and its queries are identical (`go test ./...` passes, including the sample scenarios). The other four templates are not served.
4. **The apply script.** `lab/zetaris/usl/apply.sh`. `sh -n`: exit 0. `DRY=1` with a `curl` stub that fails if called: not called, statements printed, no setting printed (`TestDryRunSendsNothing`, with and without the settings). The key reaches `curl` on a pipe, not on a command line (`TestApplyKeepsTheKeyOffTheCommandLine`). A refusal from Zetaris is printed with the key replaced (`TestApplyToleratesOnlyTheMarkedRefusals`). A missing or malformed setting stops it before any call (`TestApplyNeedsEverySetting`).
5. **The parity test.** `testdata/zetaris-usl/answers.json` holds the sample-mode answers for six requests (one per served template, two that find nothing). `TestParityRecordedAnswersMatchSampleMode` holds the recording to sample mode. `TestParityLayerReturnsTheRecordedRows` builds the layer from `layer.sql` on the local engine and requires the same rows. `TestParityComparerIsRedWhenAnExpectedRowChanges` and `TestParityIsRedWhenASourceRowChanges`: red when one cell, row or column changes. `TestParityLive` (the body of `make zetaris-usl-parity`) is skipped by name without the three Zetaris settings.
6. **Docs.** `docs/ZETARIS_USL.md`, linked from `docs/README.md`; `PROVEN_OSV_ID_VIEW` row in `docs/CONFIGURATION.md`, generated by `go run ./cmd/settings-doc` and held by `internal/settingspage`.

## Judgement calls
- No USL documentation in the repository, so plain views in one container, as the order said — cost if wrong: the first live apply shows the syntax is not the platform's, and `layer.sql` needs an edit.
- "Tolerate" lines let a `DROP` of a missing view and a `CREATE` of a present container be refused for the word "exist" — cost if wrong: the first apply stops at that statement, and the refusal is printed.
- The live parity compares the layer with its sources, not with the recording, because the live data is not the sample data — cost if wrong: the live check proves transparency and not the sample rows.
- Registration needs the administrator, so the grant to Proven's user is printed by the docs and not sent by the script — cost if wrong: one manual statement.
