## Red items (read these first)
1. **Behaviour change.** With no terminal and no setting the lab is a sample lab, as the order says, and keys in `lab/.env` are **not used** unless `PROVEN_LAB_MODE=live` is set. In round 2 a key in `lab/.env` made the reviews live. A script that relied on that now gets sample reviews, and the log says so by name (`up: sample mode does not use these settings: …`). `make e2e` and the check scripts set the mode themselves.
2. **Access token and the review job.** Proven's generator and Zetaris adapters send a Bearer token. Neither sends a `cf-access-token` header (searched: no such code or setting in the repository). The lab stores the Access token as an Actions secret and hands it to the job as the Bearer value and by name; whether a gateway behind Access accepts that is W18's side and was not run. If it does not, the CLI track must add the header.
3. **The check's route is an assumption.** The order says "an evidence-route request with an empty JSON object". The lab sends it to `JUDGES_GATEWAY_URL` plus `JUDGES_GATEWAY_ZETARIS_PATH` (default `/zetaris/api/v1.0`), the only evidence path the lab knows. Written against the contract in the order and a stub; not run against W18.
4. **A service found on the judge's machine may not be reachable by the lab's review job.** The job runs inside the lab's own Docker. The flow rewrites the host to `host.docker.internal` and says that a service listening on `127.0.0.1` only cannot be reached. Not measured.

"Stop that path cleanly" read as stop: a judge who asked for live must not be handed a sample lab that looks live. If the owner wants a fall-back to sample, it is one line.
2. A credential asked for on a terminal is kept in this run's environment only. A secret the judge typed is therefore **not kept across `make up` runs**: round 2 removes a stored secret whose setting is empty, so the next `make up` asks again (Access renews on its own). Putting the token in `lab/.env` keeps it. This follows "stored exactly as round 2 stores a key".
3. `PROVEN_LAB_JUDGE=yes` with no `PROVEN_LAB_BACKEND` and no terminal is refused by name; `PROVEN_LAB_MODE=live` with no judge setting and no terminal means not a judge. A script should not block, and choosing credentials for a judge is not a default.
4. The banner has one line the owner did not write ("No humans were harmed. Several agents were asked to try again.") for the light humour the order asked for. One line to delete.
5. `PROVEN_LAB_TTY` exists only so the tests can stand in for a terminal.
6. The ports of Gitea, Grafana, the page and the docs moved to 3300 to 3303 as the order's example gave; the Zetaris console to 3304 to stay beside them.
7. The code, the tests and the docs are three commits, and not slices of one behaviour each: the port move, the flow and the settings share files.
